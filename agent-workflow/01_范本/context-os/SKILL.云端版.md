# context-os

## 什么时候用

- 长项目、长对话要**跨会话接上**：接手时靠一份「记忆文本」就能恢复「我是谁、在干什么、东西在哪、还剩什么」。
- 有**多个 AI 分工**（指挥者/执行者），要求各自记忆独立、互不代写。
- 记忆开始膨胀：需要知道谁快满了、该压哪一份、按什么顺序压。

## 什么时候别用

- 单次问答、一次性脚本、不需要跨会话继续的活。
- 只是要产出文档/代码 —— 那是内容任务，不是上下文管理。
- 要求多个 AI 共享同一份记忆文件（本设计明确禁止）。

## 前置条件

- 一个**项目根目录**：所有记忆文件都在它下面（`ctxos\`、`memory\`）。
- 能读写文件，能跑 `node`（计量脚本只用 Node 内置模块，无第三方依赖）。
- 先定清楚**有哪些 AI**（每个 AI 一套记忆）。只有一个就写一个。

## 四分区（固定，别改口径）

| 代号 | 配额(tokens) | 装什么 | 谁写 |
|---|---|---|---|
| LTM 长期记忆 | 基准 10k（软线 8k / 硬顶 12k） | 红线、裁决、跨会话结论、接口与坑、指针 —— **像硬盘索引** | 该 AI 自己 |
| STM 短期记忆 | 100k | 工作现场「六问」 | 该 AI 自己 |
| MEMTEXT 记忆文本 | 50k | **只放索引**：记忆在哪、怎么分类、怎么恢复 | 该 AI，每轮结束覆盖写 |
| EXEC 执行空间 | 其余 | 临时推理、读进来的原文、试错 | 使用者，轮末丢弃 |

STM 六问：① 你知道什么（环境事实、已探明结论，带日期与证据）② 我们要干什么（目标与边界）③ 上一轮怎么做的 ④ 去哪找（索引）⑤ 现在做到哪 ⑥ 还剩什么。

## 怎么做（5 步）

1. **建骨架**：项目根下建 `ctxos/QUOTA.json`、`ctxos/INDEX.md`，以及每个 AI 的 `ctxos/<ai>/LTM.md`、`STM.md`、`MEMTEXT.md`；再建 `memory/journal.jsonl`（空文件即可）。
   精确字段、模板与幂等规则见 [骨架与模板](references/scaffold.md)。已存在的文件**不要覆盖** —— 记忆内容只能由它的主人写。
2. **开场 3 步**：读该 AI 的 `MEMTEXT.md` → 按其中索引只加载需要的段 → 只有需要更早细节才查上游记录。**不要整目录读**。
3. **干活时**：把变化的现场写回该 AI 的 STM 六问；只把「以后还用得上」的结论写进它的 LTM。
4. **收场 4 步**（顺序不能反）：① 原地覆盖迭代 MEMTEXT ② 回填 STM ③ 结论进 LTM ④ 记账（任务板 + 往流水追加一行）。
5. **量占用**（决定要不要压缩）：

```text
"$ORKAS_NODE" "$ORKAS_PC_DIR/bin/run-skill.cjs" context-os ctx_status -- --root <项目根>
```

不加 `--root` 时按当前目录。`QUOTA.json` 缺失或坏掉会返回 `{ok:false,error}`；分区文件缺失该分区报 `missing`。先自检（不联网、不读真实工作区）：

```text
"$ORKAS_NODE" "$ORKAS_PC_DIR/bin/run-skill.cjs" context-os ctx_status -- --selftest
```

## 压缩规则

- `tokens <= 软线` → ok
- `软线 < tokens <= 硬顶` → warn：**该压缩了**
- `tokens > 硬顶` → over：**立刻压缩**
- 分区没写 `quota_soft` 时按硬顶的 80% 兜底。

压缩顺序：① 合并同类条目 ② 删已失效条目（带日期） ③ 把细节搬进产物文件，这里只留指针。

## 输出形态

计量输出单行 JSON：

```text
{ "ok":true, "root":"<绝对路径>", "version":"...", "estimator":"ceil(cjk*1.0 + other/4)", "total_context":1000000,
  "usage": { "<ai>": { "<分区>": { "file","source","chars","cjk","other","tokens","entries","quota","quota_soft","ratio","ratio_soft","headroom","status" } } },
  "summary": { "measured_tokens","exec_space","worst_status","over":[],"warn":[],"missing":[],"next_actions":[] } }
```

体积口径：`tokens ≈ ceil(全角/CJK字符数 × 1.0 + 其它字符数 ÷ 4)`（`cjk` = 码位 > 0x2E80 的字符；粗估，只用于配额判断）。读文件按 UTF-8 并先剥掉开头 BOM。

## 铁律

1. **谁的记忆谁写**：一个 AI 的记忆只由它自己写，别的 AI 只读不写。
2. **交换只走显式通道**：任务单、交付物、显式搬运；不共享记忆文件。
3. **单份原地迭代**：不建 `.bak`、不带时间戳副本、不做版本目录、不回滚；要留痕只往流水追加一行。

设计取舍（为什么这样切、动态容量怎么来、LTM 准入标准）见 [设计说明](references/design.md)。
