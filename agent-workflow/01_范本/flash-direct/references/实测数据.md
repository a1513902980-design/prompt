# 实测数据：五组对照

**方法**：同一个任务、同一把 key、同一端点（`https://discovery-api.intern-ai.org.cn/v1`）、
同一个模型 id（`deepseek-v4-flash-0731`，端点回报 `dsv4-flash-vision`），
**只改「任务单怎么写」和「开不开推理」**。每组独立目录、独立记忆分区。

**任务**：手写递归下降表达式求值器（156~191 行），15 个功能用例 + 3 项静态检查，满分 18。

**评分**：`crawler-lab/_flash_probe/eval_probe.py`（固定不变，五组同一份）

---

## 汇总

| 组 | 配置 | 墙钟 | completion | **推理** | 产出字符 | 质量 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 默认（不干预） | 402.8s | 14198 | 12762 | 4421 | 18/18 |
| B | `--no-reasoning` | 163.7s | 4587 | 3101 | 4645 | 18/18 |
| C | B + 输出纪律 | 45.9s | 2269 | 1165 | 4180 | **15/18** |
| D | C + 完整接口契约 | 181.2s | 6444 | 5030 | 5058 | 18/18 |
| **E** | **输出纪律 + 紧凑名字清单** | **12.3s** | **1230** | **0** | 4739 | **18/18** |

prompt_tokens：A 1426 / B 1426 / C 1548 / D 1779 / E 1467

## 每组证明了什么

### A → B：`--no-reasoning` 白赚 68%

推理 12762 → 3101（−76%），耗时 402.8s → 163.7s（−59%），**质量一样是 18/18**。

> **默认那 12762 个推理 token 买到的质量提升是零。**

而且 B 只加一个命令行参数，任务单一个字没改。**这是零风险的免费优化。**

### B → C：提示词压制有效，但会静默丢东西

推理 3101 → 1165（−62%），耗时 163.7s → 45.9s。**但质量掉到 15/18。**

失败签名（这就是"静默"的意思——它看起来写完了、结构也对）：

```
evaluate('(1+2)*3') → AttributeError: '_Parser' object has no attribute '_parse_expression'
evaluate('-(2+3)')  → 同一个 AttributeError
'(1'                → 抛了 AttributeError，期望 ValueError
```

它**调了一个自己没定义的方法名**。静态检查 3/3 全过、其余 14 个用例全过——只有涉及"跨部分"的三个挂了。

> **推理负责的是「跨部分一致性检查」。压掉之后，这一层就没了。**

### C → E：把契约写成清单，而不是文档

D 和 E **想说的是同一件事**（钉死方法名），但：

| | 写法 | 推理 |
| --- | --- | --- |
| D | 带 docstring、方法体标注、树状图、警示段落的**文档** | **5030** |
| E | 一行一个名字的**清单**（6 行） | **0** |

D 甚至比 B 还贵（6444 vs 4587 completion token）——**加详细说明反而增加了它要消化的东西**。

> **说明文字越多，它要想的越多。冗余的解释本身就是认知负担。**

E 同时拿到了 C 的速度（实际更快）和满分质量：**推理 0、12.3 秒、18/18**。

## 复现方法

```bash
cd <workspace>/crawler-lab

# 五组任务单与产物都已留存
_flash_probe/    A 组（默认）
_flash_probe2/   B 组（--no-reasoning）
_flash_probe3/   C 组（+ 输出纪律）
_flash_probe4/   D 组（+ 完整接口契约）
_flash_probe5/   E 组（+ 紧凑名字清单）

# 评分脚本（五组共用，未改动）
_flash_probe/eval_probe.py
```

重跑某组：

```bash
cd crawler-lab/_flash_probe5
node <skill>/scripts/dispatch.mjs --task TASK.md --root . \
  --no-reasoning --max-tokens 16000 --idle-ms 90000 --no-map --ai <分区名>
python ../c02_details/extract.py out/TASK.<时间戳>.md expr.py
python eval_probe.py expr.py          # 退出码 0 = 满分
```

> **评测陷阱提醒**：`eval_probe.py` 的「无省略占位」检查会把文档字符串里的 `...`
> 误报成省略（A 组就因此被扣了 1 分，实际是 18/18）。
> 看结果时要区分「真缺陷」和「检查器太粗」。

## 已知局限

1. **样本是 1 个任务、每组 1 次**。结论趋势明确（33 倍差距远超噪声），但不是统计显著。
2. **只测了 4.0flash / `dsv4-flash-vision` 这一个端点**。换模型要重测——尤其"名字清单能压到 0 推理"这条，可能依赖该端点的具体实现。
3. **任务类型单一**（写代码）。改写/抽取/翻译类任务没测，但机制上属于同一族：**判断点消掉，推理就降**。
4. **`reasoning: false` 没有把推理压到 0**（B/C/D 组都还有残余），说明端点只是部分遵守；E 组的 0 是"任务单没有可想的点"与"参数关闭"叠加的结果。
